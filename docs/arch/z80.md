# Z80 / Z180

Part of [Development style](../development-style.md): read General first.

**Pitfalls.** The byte bus takes one byte per read, so `regs_z80.cpp` uses
sequential-cursor injection and the faked `POP` throughout (see General,
Injection models: sequential cursor vs address-keyed). **[code]** The Z80,
NSC800 and KL5C80 `completeCycle()` treat an I/O address as 8-bit and ignore
the high byte, so high-byte bugs stay hidden there; the Z180's decodes all
16 bits, its USART being at 0140H. **[code]**

**CP/M disk.** `DevsZ80` puts the sector disk 10H above its USART: 50H on
the 8-bit boards, which boot the 8080's CP/M unchanged, and 0150H on the
Z180, Z280 and Z380, which decode 16 bits and need a BIOS using
`OUT (C),A`. Their MMUs map one to one at reset, so DMA is physical. The
Z280 runs uncached (the debugger's reset writes 60H to Cache Control), so
sectors the disk writes behind the CPU are never stale. **[code]**
