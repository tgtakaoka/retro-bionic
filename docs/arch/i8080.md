# 8080

Part of [Development style](../development-style.md): read General first.

**Pitfalls.** `prepareCycle()` must not sample SYNC before tDC (150 ns max)
or status before tDD (220 ns max) after PHI2 rises. SYNC sampled early
misses T1; the status is then read in T2 from a released bus, some reads
look like writes, and stale bus data is written over code. **[hw]**

Compare memory with the loaded image after a run to tell bus errors from
program bugs: bus corruption hits operands the CPU has been reading. **[hw]**

The NMOS 8080 is dynamic (tCY max 2 us), but clock stretching is not a
cause of such corruption: a pulse-width trigger on PHI1 armed during
failing runs never fired. **[hw]**

PHI1 and PHI2 run free from the B and A outputs of FlexPWM3 submodule 1
(P53 and P47, board rev 3), so one counter times both. On rev 2 they
came from FlexPWM2 and FlexPWM3: an XBAR sync from one to the other's
EXT_SYNC never started the second counter, so the two were restarted
back to back with FORCE, and PHI2's edges were set 4 counts early for
the gap between the writes. Rev 2's passive level shifters (a rise of
about 100 ns, PHI1 peaking near 8.4 V) needed phases as wide as the
bit-banged ones, which topped the clock at 2.5 MHz. **[hw]** Rev 3's gate
driver (UCC27324 + 33 ohm) swings the full 11 V, but at the socket it
turns on about 40 ns and off about 60 ns after the Teensy edge (8 V /
1 V levels), so a phase is some 30 ns narrower there and the gaps lose
20 ns; PHI1 needs 80 ns at the Teensy to hold tPHI1. 150 MHz / 58 gives
2.59 MHz with PHI1 80 ns, tD1 40 ns, PHI2 180 ns and tD2 87 ns at the
Teensy (measured with no CPU, Logic analog at 50 MS/s, which reads short
pulses low; a scope may allow more). The firmware had allowed the driver
40 ns: the status was read 5 ns before tDD and READY's hold window ended
before the CPU's PHI2 fall, so long runs hit a wrong status; now 70 ns.
K only narrows PHI2: 57 counts fails echoitr and 48 fails every run, so
58 is the limit of this layout, with one count of margin. **[hw]**

- READY must change outside the window where PHI2's fall samples it:
  raised there, it missed tRS and the CPU went on with part of its state
  waiting, reading memory without fetches until it ran into the weeds.
  `raise_ready()` waits on PHI1's counter.
- The status is on D0-D7 only around SYNC, so the cycle the CPU waits in
  carries it in its ring slot; `Cycles::reset()` rewinds to a stale slot,
  so `resetCycles()` moves the waiting cycle along.
- In a run, a plain memory read is served without a wait state: READY
  goes high again as soon as the status shows it, and the data is driven
  the moment DBIN rises (see General, Clocking a run from a timer); the
  devices change INT only while the CPU waits. **[hw][code]**

**CP/M disk.** An I/O cycle holds the CPU at READY for as long as the
Teensy takes, so the sector disk moves a whole sector, an SD card
access of milliseconds, inside the OUT to its command port; the next
IN reads the status. A DMA address is a 16-bit memory address and
wraps. The images open at the prompt, when `L` loads the cold boot or
`O` mounts one, never in a transfer, and an image that is not there is
not made. The BIOS picks
each drive's DPB and skew table by the format DRIVE reads back:
`hd8`, 8 MB with no skew, or the 8" single-density ones of DRI's
skeletal `CBIOS.ASM`, the format cpmtools calls `ibm-3740`. The
disk's ports keep clear of the Z180's internal I/O below 40H, for a
Z80 port. **[code]**
